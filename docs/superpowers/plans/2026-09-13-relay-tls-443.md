# Relay TURN over TLS on 443 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** coturn serves TURN over TLS on 443 with a mounted certificate that renews without a restart, and a TLS listener that fails to come up is visible as an unhealthy container.

**Architecture:** `turnserver.conf` moves TLS to 443 and names the certificate; the relay compose file runs coturn as `nobody` with only `NET_BIND_SERVICE`, mounts the certificate directory, and health-checks a TLS handshake on 443. `deploy/coturn/install-cert.sh` is certbot's deploy hook: it validates the pair, installs it with coturn-readable permissions, and sends `SIGUSR2`. `scripts/check-relay.sh` drives the real compose file with throwaway certificates and is the test for all of it.

**Tech Stack:** coturn 4.6 (`coturn/coturn:4.6`), Docker Compose, bash, openssl. No Rust, web or API changes.

**Spec:** `docs/superpowers/specs/2026-09-11-relay-tls-443-design.md`

## Global Constraints

- Branch `relay-tls-443`. The repo-root `Cargo.toml` carries a local, uncommitted `[patch.crates-io]` entry: never stage it, never `git add .` or `git add -A` — stage files by name.
- Commit messages are one plain sentence in the repository's style, plus any trailer the session's commit instructions require.
- Nothing tracked may match `publish.sh`'s leak check. Before each commit, run it against the staged files: `bash -c 'source <(sed -n "28,30p" publish.sh); git diff --cached --name-only | xargs -r grep -lniE "$LEAKS"'` — expected output: nothing. The private notes file that `publish.sh` excludes (see its line 8) is exempt; nothing else is.
- Image `coturn/coturn:4.6`. TLS port `443`, replacing `5349`. Plain TURN stays on `3478` UDP and TCP.
- Certificate paths inside the container: `/etc/coturn/certs/fullchain.pem`, `/etc/coturn/certs/privkey.pem`.
- Installed permissions: certificate directory `0750`, `fullchain.pem` `0644`, `privkey.pem` `0640`; directory and key group `CERT_GROUP`, default `65534`.
- Compose: project `name: coturn`; `cap_drop: [ALL]`, `cap_add: [NET_BIND_SERVICE]`; `group_add: ["${RTC_TURN_CERT_GROUP:-65534}"]`; certificate volume `${RTC_TURN_CERT_DIR:-./certs}:/etc/coturn/certs:ro`; healthcheck `["CMD", "bash", "-c", "timeout 5 openssl s_client -connect 127.0.0.1:443 -brief </dev/null"]`, `interval: 10s`, `timeout: 8s`, `retries: 3`, `start_period: 10s`.
- Check waits: 30 s for 443 to present the first certificate, 60 s for `healthy`, 10 s for a renewed certificate, 60 s for `unhealthy`.
- Running the check needs Docker with `coturn/coturn:4.6` available, `openssl`, `ss`, and nothing listening on 443 or 3478. It refuses to start otherwise.
- Facts established by probing, relied on below: `turnutils_uclient` exits 255 on success and failure alike; with the right secret its output contains `error 403 (Forbidden IP)` (the loopback peer is blacklisted, which coturn only checks inside an authenticated allocation); with a wrong secret it contains `Cannot complete Allocation`. `openssl s_client` exits 0 when 443 answers and 1 when nothing listens.

- [ ] **Step 1: Write the check.** Create `scripts/check-relay.sh`:

```bash
#!/usr/bin/env bash
# The relay's TLS side, checked against the real compose file with a throwaway
# certificate: TURN over TLS on 443, an authenticated allocation, and a
# healthcheck that notices when coturn quietly starts without TLS.
#
#   make check-relay
#
# Needs Docker, openssl, and ports 443 and 3478 free. See docs/TURN-DEPLOY.md.
set -euo pipefail

ROOT="$(cd "$(dirname "$0")/.." && pwd)"
COMPOSE=(docker compose -f "$ROOT/deploy/coturn/docker-compose.yml")
IMAGE=coturn/coturn:4.6

fail() { echo "FAIL: $*" >&2; exit 1; }

printf '1/7 ports 443 and 3478 are free... '
# First, and before the cleanup trap exists: that trap stops the coturn compose
# project, which would be somebody's real relay if one is running here.
if ss -ltn | grep -qE ':(443|3478)\b'; then
  fail "something already listens on 443 or 3478"
fi
echo ok

WORK="$(mktemp -d)"
RTC_TURN_SECRET="$(openssl rand -hex 16)"
RTC_TURN_CERT_GROUP="$(id -g)"
export RTC_TURN_REALM=relay.test RTC_TURN_PUBLIC_IP=127.0.0.1 RTC_TURN_SECRET RTC_TURN_CERT_GROUP
export RTC_TURN_CERT_DIR="$WORK/certs"
cleanup() {
  "${COMPOSE[@]}" down --timeout 2 >/dev/null 2>&1 || true
  rm -rf "$WORK"
}
trap cleanup EXIT

# A self-signed pair, laid out the way certbot lays out a lineage.
make_cert() {
  mkdir -p "$1"
  openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:prime256v1 -nodes \
    -keyout "$1/privkey.pem" -out "$1/fullchain.pem" -days 1 -subj /CN=relay.test 2>/dev/null
}
serial_of() { openssl x509 -in "$1" -noout -serial; }
served_serial() {
  timeout 5 openssl s_client -connect 127.0.0.1:443 -servername relay.test </dev/null 2>/dev/null \
    | openssl x509 -noout -serial 2>/dev/null || true
}
presents() { [[ "$(served_serial)" == "$1" ]]; }
container() { "${COMPOSE[@]}" ps -q coturn; }
health() {
  docker inspect -f '{{if .State.Health}}{{.State.Health.Status}}{{else}}none{{end}}' "$(container)" 2>/dev/null \
    || echo gone
}
health_is() { [[ "$(health)" == "$1" ]]; }
# wait_for SECONDS COMMAND... -- retry once a second until it succeeds or time is up.
wait_for() {
  local deadline=$((SECONDS + $1)); shift
  until "$@"; do
    (( SECONDS < deadline )) || return 1
    sleep 1
  done
}
uclient() {
  timeout 30 docker run --rm --network host --entrypoint turnutils_uclient "$IMAGE" \
    -S -t -p 443 -W "$1" -u check -n 1 -m 1 -y 127.0.0.1 2>&1 || true
}

printf '2/7 certificate A in place... '
make_cert "$WORK/a"
SERIAL_A="$(serial_of "$WORK/a/fullchain.pem")"
mkdir -p "$RTC_TURN_CERT_DIR"
chmod 0750 "$RTC_TURN_CERT_DIR"
install -m 0644 "$WORK/a/fullchain.pem" "$RTC_TURN_CERT_DIR/fullchain.pem"
install -m 0640 -g "$RTC_TURN_CERT_GROUP" "$WORK/a/privkey.pem" "$RTC_TURN_CERT_DIR/privkey.pem"
echo ok

printf '3/7 443 presents certificate A... '
"${COMPOSE[@]}" up -d >/dev/null
wait_for 30 presents "$SERIAL_A" || fail "443 does not present certificate A (got '$(served_serial)')"
echo ok

printf '4/7 the healthcheck passes... '
wait_for 60 health_is healthy || fail "relay health is '$(health)', expected healthy"
echo ok

printf '5/7 an allocation over TLS authenticates with the shared secret... '
out="$(uclient "$RTC_TURN_SECRET")"
# coturn checks the peer address only inside an authenticated allocation, and
# the shipped blacklist forbids loopback peers: this 403 means we got that far.
grep -q 'error 403 (Forbidden IP)' <<<"$out" || fail "no authenticated allocation over TLS: $out"
echo ok

printf '6/7 a wrong secret cannot allocate over TLS... '
out="$(uclient "wrong-$RTC_TURN_SECRET")"
grep -q 'Cannot complete Allocation' <<<"$out" || fail "a wrong secret was not refused: $out"
echo ok

printf '7/7 an unreadable key turns the relay unhealthy... '
chmod 0600 "$RTC_TURN_CERT_DIR/privkey.pem"
"${COMPOSE[@]}" restart coturn >/dev/null
wait_for 60 health_is unhealthy || fail "relay health is '$(health)' with an unreadable key, expected unhealthy"
echo ok

echo "Relay check passed."
```

- [ ] **Step 4: Rewrite the compose file.** Replace the whole of `deploy/coturn/docker-compose.yml` with:

```yaml
# The relay, on its own.
#
# TURN is separate from the rest on purpose. It wants bandwidth and nothing
# else, so it belongs on a cheap flat-rate box rather than beside the API — and
# on a hyperscaler the same traffic costs about a hundred times more. That is
# the finding in docs/TURN-COSTS.md, and it is the reason this file exists
# apart from the main one.
#
#   RTC_TURN_PUBLIC_IP=203.0.113.10 \
#   RTC_TURN_REALM=relay.example.com \
#   RTC_TURN_SECRET=... \
#     docker compose -f deploy/coturn/docker-compose.yml up -d
#
# The same secret goes to the API as RTC_TURN_SECRET. Nothing else is shared.
# TURN over TLS on 443 needs a certificate in ./certs before this starts;
# docs/TURN-DEPLOY.md says how.

# Fixed, so the containers carry the same project label wherever this file is
# run from. The certificate hook finds the relay by that label.
name: coturn

services:
  coturn:
    image: coturn/coturn:4.6
    # Host networking on purpose. A relay needs a wide UDP port range, and
    # publishing forty ports through the docker proxy is slow to start and a
    # needless hop on every packet. It also lets coturn see real client
    # addresses instead of the bridge's.
    network_mode: host
    # coturn runs as the image's own user, nobody. Under host networking,
    # binding 443 takes exactly one capability, so it is declared here rather
    # than inherited from Docker's defaults, and everything else is dropped.
    cap_drop: [ALL]
    cap_add: [NET_BIND_SERVICE]
    # The key is installed 0640 in this group: nobody's own group in
    # production. The relay check sets it to the caller's group so it can run
    # the real permission rule without root.
    group_add: ["${RTC_TURN_CERT_GROUP:-65534}"]
    volumes:
      - ./turnserver.conf:/etc/coturn/turnserver.conf:ro
      - ${RTC_TURN_CERT_DIR:-./certs}:/etc/coturn/certs:ro
    # A missing or unreadable certificate does not stop coturn: it runs with no
    # TLS listener and logs that once. A handshake on 443 is the check that
    # tells, rather than sites that quietly cannot connect.
    healthcheck:
      test: ["CMD", "bash", "-c", "timeout 5 openssl s_client -connect 127.0.0.1:443 -brief </dev/null"]
      interval: 10s
      timeout: 8s
      retries: 3
      start_period: 10s
    # coturn does not read these from the environment, so they arrive as flags.
    # They are visible in `ps` on the host: acceptable when the host is yours,
    # and worth knowing when it is not.
    command: >
      -c /etc/coturn/turnserver.conf
      --realm=${RTC_TURN_REALM:?set the realm, e.g. relay.example.com}
      --external-ip=${RTC_TURN_PUBLIC_IP:?set the public address of this box}
      --static-auth-secret=${RTC_TURN_SECRET:?set the same secret the api uses}
    restart: unless-stopped
```

- [ ] **Step 3: Write the hook.** Create `deploy/coturn/install-cert.sh`:

```bash
#!/usr/bin/env bash
# Install a certificate for the relay and make coturn pick it up.
#
# certbot runs this as a deploy hook, after the first issuance and after every
# renewal, with RENEWED_LINEAGE set to /etc/letsencrypt/live/<name>:
#
#   certbot certonly --standalone -d relay.example.com \
#     --deploy-hook /path/to/relaysight/deploy/coturn/install-cert.sh
#
# It copies instead of pointing coturn at /etc/letsencrypt: the files there are
# symlinks into archive/ and the key is readable by root only, while coturn
# runs as nobody. See docs/TURN-DEPLOY.md.
set -euo pipefail

: "${RENEWED_LINEAGE:?set RENEWED_LINEAGE to the directory holding fullchain.pem and privkey.pem}"
CERT_DIR="${CERT_DIR:-$(cd "$(dirname "$0")" && pwd)/certs}"
CERT_GROUP="${CERT_GROUP:-65534}"

chain="$RENEWED_LINEAGE/fullchain.pem"
key="$RENEWED_LINEAGE/privkey.pem"
for file in "$chain" "$key"; do
  [[ -r "$file" ]] || { echo "install-cert: cannot read $file; nothing installed" >&2; exit 1; }
done

# A key that does not belong to the certificate takes TLS down with nothing but
# an unhealthy container to show for it. Refuse it here, before anything moves.
# Assignments, not inline substitutions, so an openssl failure stops the script
# instead of comparing two empty strings.
cert_public="$(openssl x509 -in "$chain" -noout -pubkey)"
key_public="$(openssl pkey -in "$key" -pubout)"
if [[ "$cert_public" != "$key_public" ]]; then
  echo "install-cert: $key does not belong to $chain; nothing installed" >&2
  exit 1
fi

mkdir -p "$CERT_DIR"
chgrp "$CERT_GROUP" "$CERT_DIR"
chmod 0750 "$CERT_DIR"

# Temporary names in the same directory, then rename: a reload never reads a
# file that is still being written.
tmp_chain="$(mktemp "$CERT_DIR/.fullchain.XXXXXX")"
tmp_key="$(mktemp "$CERT_DIR/.privkey.XXXXXX")"
trap 'rm -f "$tmp_chain" "$tmp_key"' EXIT
cat "$chain" >"$tmp_chain"
cat "$key" >"$tmp_key"
chmod 0644 "$tmp_chain"
chgrp "$CERT_GROUP" "$tmp_key"
chmod 0640 "$tmp_key"
mv -f "$tmp_chain" "$CERT_DIR/fullchain.pem"
mv -f "$tmp_key" "$CERT_DIR/privkey.pem"

relay="$(docker ps -q \
  --filter label=com.docker.compose.project=coturn \
  --filter label=com.docker.compose.service=coturn)"
if [[ -z "$relay" ]]; then
  echo "install-cert: installed in $CERT_DIR; coturn is not running and will read it when it starts"
  exit 0
fi
# SIGUSR2 makes coturn reload its certificate and key without a restart.
docker kill --signal SIGUSR2 "$relay" >/dev/null
echo "install-cert: installed in $CERT_DIR and signalled coturn to reload"
```

Then `chmod +x deploy/coturn/install-cert.sh`.

## The certificate

TURN over TLS needs a certificate for the realm. coturn reads it from
`deploy/coturn/certs/` (or wherever `RTC_TURN_CERT_DIR` points), and

issuance and after every renewal:

```
certbot certonly --standalone -d relay.example.com \
  --deploy-hook /path/to/relaysight/deploy/coturn/install-cert.sh
```

`--standalone` answers the challenge itself on port 80, so 80 has to be open to
the box while certbot runs.

The hook copies instead of pointing coturn at `/etc/letsencrypt/live`, because
the files there are symlinks into `archive/` and the key is readable by root
only, while coturn runs as `nobody`. It installs the key 0640 in group 65534,
which is `nobody`'s, refuses a key that does not belong to its certificate, and
sends coturn `SIGUSR2`, which reloads the pair without a restart.

Put the first certificate in place before starting the relay. Started without
one, coturn does not fail: it runs with no TLS listener and says so once in its
log. The compose healthcheck is a TLS handshake on 443, so that state shows up
as `unhealthy` in `docker compose ps` instead of as sites that quietly cannot
connect.
